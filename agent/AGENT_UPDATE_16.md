## 3. Task 1 — Detect the source language and dub into Vietnamese from any language

### 3.1 Settings and UI
- Config `asr.language: auto` (default) or a language code (`en`, `ja`, `zh`, `ko`, `es`, `fr`, `de`, `ru`, `pt`, `it`, `th`, `hi`, `ar`, `id`, … any code the speech-recognition model supports).
- Main window: a compact row **"Ngôn ngữ video"** (dropdown) in the main area above the model row: *Tự động nhận diện* (default), then a curated list with native and Vietnamese names (English, 日本語 Nhật, 中文 Trung, 한국어 Hàn, Español Tây Ban Nha, Français Pháp, Deutsch Đức, Русский Nga, Português Bồ Đào Nha, Italiano Ý, ภาษาไทย Thái, हिन्दी Hindi, العربية Ả Rập, Bahasa Indonesia), then **"Khác…"** that lists every language the model supports (`whisper.tokenizer.LANGUAGES` or the equivalent in the installed library). Disabled while a run is in progress. Not remembered between runs (always starts at "Tự động").
- The stage row and the details panel show the result: "Ngôn ngữ: English (98%)" or "Ngôn ngữ: 日本語 (91%), đã nhận diện tự động"; with a manual choice: "Ngôn ngữ: 日本語 (chọn tay)".
- If the model is an English-only variant (`*.en`), refuse non-English input with a clear message; the Whisper dropdown lists multilingual models only.
- Add the same options to the CLI and the headless run: `--source-language auto|<code>`.

### 3.2 Detection (stage 2)
- Check the installed `faster-whisper` signature for `transcribe` and `detect_language` (parameters such as `language`, `multilingual`, `language_detection_segments`, `language_detection_threshold`); use what exists and **report the version and what you found**.
- Procedure for `auto`: detect on up to **3 windows that contain speech** (use the voice-activity detector; for example the first speech region, one near the middle, one near the end), each with a probability; the result is the language with the highest mean probability. Store in `state.json`: `source_language: {code, name, probability, method, windows: [{start, language, probability}]}`.
- **Uncertain** (best probability < `asr.language_min_confidence`, default 0.60, or two languages each present in at least 25% of the windows): GUI → a dialog with the top 3 candidates and their probabilities (the user picks or cancels); CLI and headless → continue with the best candidate, log a warning, and record `uncertain: true`.
- **Mixed-language video:** if the installed library supports per-segment language detection (`multilingual=True` or equivalent), use it and store a `language` per segment; otherwise keep a single language, warn "video có nhiều ngôn ngữ; một số đoạn có thể nhận dạng sai", and say in the report which case applies.
- **Vietnamese detected** (probability ≥ the minimum): stop before translation with the message "Video có vẻ đã là tiếng Việt (độ tin cậy X%). Không cần dịch." and offer, as a button in the GUI and `--subtitles-only` in the CLI, to create a subtitle file (`.srt`) and the readable transcript from the recognized text only. Do not call a translation or voice service in this case.
- Detection runs once per job; its result and the language setting are part of `inputs_hash`.

### 3.3 Language-aware text handling (find every English assumption and fix it)
Audit the code for English-specific logic and make it depend on the source language code. At least:
- **Sentence boundaries** (`build_units`, `resegment_by_sentences`): sentence-final marks by script: Latin `. ? ! …`, Spanish inverted marks (`¿ ¡` open a sentence; the closing marks end it), CJK `。！？`, Arabic `؟ ۔`, Devanagari `।`, and closing quotes or brackets after them. The abbreviation stop-list (`Mr.`, `Dr.`, …) applies **only to English** (other languages get no list unless one is added to a per-language table). For scripts without spaces or without sentence punctuation (Thai, Lao, Khmer), split on pauses (`units.pause_split_s`) and the unit caps.
- **Word-based rules** that split on spaces (repeat collapsing at segment boundaries, the 3-word duplicate rule, word counts for the "unpunctuated run" trigger): for Chinese, Japanese, Thai, and similar languages use the recognizer's word or token timestamps or skip the rule, and say which.
- **Punctuation restoration prompt** and its word-sequence validation: pass the language name; the validation compares tokens in a way that works for scripts without spaces (compare the sequence of non-punctuation characters instead of words).
- **Fillers and vocatives:** the lists are English; for any other language skip the detector (no change in behavior) unless a list for that language exists in `fillers.yaml`. The translation prompt must not tell the model about English fillers for other languages.
- **`asr.initial_prompt`** (an English punctuated sample) is used only when the language is English.
- **Translation and shortening prompts:** "Translate from {source language name} to Vietnamese", the glossary keyed by source term, the brief unchanged; keep every rule of Updates 8 and 12 (complete sentences, no dropped negations, no "ta", pronoun policy). The character budget stays Vietnamese-based (duration × `chars_per_sec`); do **not** compare with the source text length.
- **Readable translation file:** the header says "{language name} → Tiếng Việt", the column title "Bản gốc ({language name})" (in the app language), and the texts keep their script. For right-to-left sources (Arabic, Hebrew, Persian, Urdu) set the paragraph direction (`w:bidi`) and right alignment in the original-language column; set a script-appropriate font fallback for the original column (CJK, Arabic, Thai, Devanagari fonts that exist on Windows), keeping Arial for Vietnamese. The `.txt` format is UTF-8 with BOM as before.
- **Subtitles burned into the video** are Vietnamese only; no change.
- **Data:** `transcript.json` keeps its contract (optional `language` per segment); `dub_units.json` and the readable export carry `source_language`.

### 3.4 Quality notes shown to the user
When the detected language is not English and the Whisper model is `small` or `base`, show a one-line, non-blocking tip in the details panel ("Ngôn ngữ này nhận dạng chính xác hơn với mô hình medium (chậm hơn)"). When the detection is uncertain or the video is mixed, say so in the run summary. The first-run privacy notice already says the recognized text goes to the translation provider; it must now say "văn bản gốc (ngôn ngữ nhận diện được)".

### 3.5 Tests (offline unit tests and real-widget tests)
- Language detection with a fake model: majority vote over windows, the low-confidence dialog (real widgets, three candidates), headless fallback with a warning, a Vietnamese result stops the run and offers subtitles only, a mixed-language result, an English-only model refusing non-English input.
- Sentence splitting for English, Spanish (`¿…?`), Chinese and Japanese (`。`), Arabic (`؟`), Hindi (`।`), and a Thai sample without punctuation; the abbreviation list applies only to English; the space-based rules are off for Chinese, Japanese, and Thai.
- Prompts contain the language name; the filler detector is skipped for non-English; `initial_prompt` is not used for non-English.
- The readable file: header and column titles per language; `w:bidi` and right alignment for an Arabic sample; the font setting for a CJK sample (check the document XML).
- The dropdown, the "Khác…" list, the manual choice skipping detection, the disabled state while busy, and the CLI flag.
- Regression: English input with `auto` yields the same units as with `en` on a fixture.

### 3.6 Real verification (this is the part that must not be skipped)
1. **Create short test clips in other languages** with the voices of `edge-tts` (the service is not always reliable; retry later or use another voice if it refuses): about 40–60 seconds each of 8–10 original sentences on neutral topics that you write yourself: **Japanese, Chinese, Korean, Spanish, French, German, Arabic**. Also create one **mixed** clip alternating English and Spanish sentences, and one **Vietnamese** clip. State in the report that synthetic speech is cleaner than real speech, so real accuracy will be lower.
2. For each clip run the full pipeline with `gemini-3.5-flash-lite` (language `auto`) from the packaged exe and report: the detected code and probability, the windows, the first 3 recognized lines, the number of units, the first 5 units (source text and Vietnamese, raw), whether the readable document was created, and for Arabic the check of the right-to-left settings in the document XML. For the Vietnamese clip show the stop message and the subtitles-only output; for the mixed clip show what the library supports and what the run produced.
3. Do not say that translations are good; show them and let the user read.
4. **English regression:** run `test9.mp4` with `auto` and compare with the Update 15 result (`evidence_table.py` on both jobs): the unit count, the TTS request count, and the fit statuses must match within the natural variation of the recognizer; explain any difference.

## 5. Task 3 — Analyze the voice failures properly, then decide the defaults by rule

### 5.1 Classification
In `scripts/validate_voice_settings.py` (and `--tts-probe`), classify every failure by the **root cause**: walk `__cause__` and `__context__` to the innermost exception and count by its class name and, for handshake errors, the HTTP status. The table must have no generic `TTSFailure` bucket. Add a test with a wrapped fake exception.

### 5.2 Length and content analysis
- Use at least **120 real texts** from the Vietnamese output of `test9.mp4` and the synthetic clips, covering all lengths, plus **length-matched controls**: each real text also has a control of the same length made of a fixed neutral sentence repeated, in the same randomized order.
- Report acceptance by length bucket (≤40, 41–80, 81–120, >120 characters) and by number of sentences, with 95% Wilson intervals, **separately for real texts and controls** (so that length and content can be told apart), in the exe and from source, in one randomized interleaved window.
- **Rule:** if acceptance for >80 characters is lower than for ≤40 by at least 15 points with non-overlapping intervals **for both** real texts and controls, implement **length-aware splitting** (split at clause punctuation above `tts.max_chars_per_request`, same voice, join with 80 ms of silence, behind a config key) and validate it in 5.3; if only the real texts show the effect, report that content, not length, is the likely factor and implement nothing; if neither shows it, report that no effect was found.

### 5.3 A/B on the real video (replaces the probe as the basis of the decision)
Using the translated job of `test9.mp4` (so that only voice generation varies), run stage 4 with **A = the Update 14 settings** and **B = the conservative Update 12 settings**, alternating A, B, B, A (4 runs; clear the clip cache between runs). For each run report: total TTS time, requests, refusals by root cause, attempts per unit, repair-ladder steps, and the voice count.

### 5.4 Decision rule (apply it, and record it as a decision on the user's behalf)
Keep A in `config.yaml` **only if** A's mean TTS time is at least 15% lower than B's **and** A's refusals per request are not higher than B's by 10 points or more. Otherwise set the defaults to B. Whatever the outcome, write the numbers and the rule in the report. If the service state during the runs was unhealthy (a control below 90%), repeat the four runs at another time and report both sets.
